# Методика визуальной дорожной карты поездки

Статус: рабочий стандарт для FairSPV / семейных дорожных карт / HTML-плакатов.

Основано на удачном варианте плаката «Китай 2026 — семейная дорожная карта»: вертикальная маршрутная таблица, спокойная светлая гамма, понятные блоки транспорта, проживания и впечатлений, визуальная колонка с образами мест.

## 1. Главная идея

Такой файл должен быть не просто красивой картинкой, а навигационным документом. Его задача — за 20–30 секунд показать:

- откуда начинается маршрут и где заканчивается;
- кто летит / едет на каждом участке;
- где семья живет по датам;
- что уже куплено и что осталось купить;
- где возможны ошибки по билетам, времени, аэропортам или отелям;
- какие впечатления ожидаются в каждом месте.

Формула документа:

> слева — линейное движение, в центре — проживание, справа — смысл остановки, крайняя правая полоса — визуальные образы.

## 2. Формат композиции

### 2.1. Основной формат

Для плаката использовать вертикальный формат, близкий к A3/A2 или длинному web-постеру:

- вертикальная ориентация;
- крупная шапка;
- ниже таблица-маршрут;
- внизу компактный блок «купить заранее» и состав семьи;
- справа узкая визуальная колонка с миниатюрами мест.

Рекомендуемые пропорции: примерно 3:4 или 4:5. Для печати лучше делать 300 dpi, для экрана достаточно 1400–2000 px по высоте.

### 2.2. Структура шапки

Шапка должна работать как афиша путешествия:

- крупный заголовок: `Китай 2026` / `Семейная дорожная карта`;
- подзаголовок: маршрут, даты, общий смысл;
- слева или справа мягкая панорама ключевых образов: карстовые горы, река, городские огни, аэропорт, животные;
- не перегружать шапку мелкими данными.

Пример:

```text
Китай 2026
семейная дорожная карта
Маршрут, размещение и впечатления • 22–30 июля 2026
```

## 3. Цветовая гамма

Использовать светлую, спокойную, «бумажную» палитру. Документ должен восприниматься как аккуратная путевая карта, а не рекламный баннер.

### 3.1. Базовые цвета

- фон: теплый молочный / слоновая кость `#f7f1df`, `#fbf7ea`;
- карточки: почти белый `#fffdf5`;
- линии таблицы: песочный / светло-золотой `#d8c28a`;
- заголовки таблицы: глубокий темно-бирюзовый `#073f46`, `#0b4a52`;
- основной текст: темный графит `#183035`, `#243236`;
- вторичный текст: серо-зеленый / приглушенный `#566b68`;
- акценты: мягкое золото, темная бирюза, приглушенный синий.

### 3.2. Запреты

Не использовать:

- кислотные цвета;
- чистый черный на больших площадях;
- ярко-красные предупреждения, если это не аварийный блок;
- много разных цветов для статусов;
- пестрые градиенты под текстом.

Предупреждения лучше делать теплым янтарным блоком, а не красной тревожной плашкой.

## 4. Типографика

### 4.1. Заголовки

Для крупного заголовка можно использовать антикву / мягкий serif, если доступно. Важно ощущение «путешественного журнала».

Рекомендации:

- заголовок: крупный serif или элегантный display-font;
- таблица и карточки: читаемый sans-serif;
- не более двух семейств шрифтов;
- цифры и рейсы должны быть максимально читаемыми.

### 4.2. Размеры

- заголовок: очень крупный, главный визуальный якорь;
- названия городов/этапов: жирные;
- детали рейсов: средний размер, но не мелкая сноска;
- длинные списки пассажиров лучше дробить строками, а не запихивать в одну строку.

## 5. Логика таблицы маршрута

Таблица должна быть линейной. Никаких хаотичных стрелок, диаграмм-осьминогов и сложных маршрутов, если задача — семейная навигация.

### 5.1. Колонки

Обязательные колонки:

1. **Транспорт и маршрут**
2. **Где живем / где находимся**
3. **Что смотрим / план**
4. **Образ места** — узкая колонка с фото/иллюстрацией

В HTML-версии можно оставить 3 колонки, а изображения добавить отдельной правой колонкой или карточками внутри строк.

### 5.2. Строки

Каждая строка — один этап маршрута:

- стартовый город;
- перелет;
- трансфер;
- заселение;
- день осмотра;
- поезд;
- техническая ночь;
- финальный перелет;
- конец маршрута.

Маршрут идет строго сверху вниз. Слева можно добавить вертикальную линию с номерами этапов.

### 5.3. Единый формат аэропортов

Всегда использовать единый формат:

```text
IATA / город, аэропорт, терминал
```

Примеры:

```text
LED / Санкт-Петербург, Пулково T1
PEK / Пекин Capital T2
PKX / Пекин Daxing
KWL / Гуйлинь Liangjiang T2
SZX / Шэньчжэнь Bao’an T3
```

Не писать в одном месте только `PEK`, а в другом `Пекин Capital`. Вся карта должна говорить одним языком.

## 6. Данные по перелетам

Каждый перелет должен содержать:

- дату;
- маршрут;
- аэропорт отправления в едином формате;
- аэропорт прибытия в едином формате;
- номер рейса;
- авиакомпанию;
- время вылета и прилета;
- время в пути, если известно;
- кто летит;
- статус: куплено / проверить / изменить.

### 6.1. Формат пассажиров

Если есть одинаковые имена, обязательно различать их стабильно во всем документе.

Пример:

```text
Александр-старший
Александр-младший
Варвара
Ольга
```

Во всех блоках использовать одни и те же обозначения. Не менять между строками на `папа`, `сын`, `Aleksandr`, `A. Shedko` без необходимости.

### 6.2. Проверка пачек билетов

Перед финализацией карты проверять билеты не по одному PDF, а пачками:

- сколько людей должно лететь;
- сколько PDF/маршрут-квитанций найдено;
- все ли на одном рейсе;
- совпадают ли дата, время, аэропорты и терминалы;
- нет ли старого/отмененного билета в папке;
- нет ли одного пассажира на другом рейсе.

Если обнаружен разнобой, в карте делать отдельный блок:

```text
ПРОВЕРИТЬ: найдено 2 билета на рейс X и 1 билет на рейс Y.
```

Не замазывать проблему красивой схемой.

## 7. Данные по отелям

Каждый отель должен иметь карточку с одинаковой структурой:

- название отеля;
- город / район;
- даты заезда и выезда;
- количество ночей;
- тип номера;
- кровати;
- кто живет;
- питание / завтрак;
- номер бронирования / confirmation no. / booking no.;
- статус оплаты;
- важное условие отмены, если есть;
- короткая роль отеля в маршруте.

### 7.1. Не писать мусорные опознаватели

Не писать в основной карточке:

```text
папка Отель Яшно 23.07-25.07 / English check-in voucher
```

Это не помогает семье. Вместо этого писать:

```text
Booking No. 1539...
Confirmation No. ...
Voucher: Trip.com check-in voucher
```

Папки и файловую структуру можно вынести в раздел документов внизу.

## 8. Блок «что смотрим»

Писать не набор слов, а смысл дня. Плохо:

```text
Sea World / Shekou / Nanshan / BYD
```

Хорошо:

```text
Вечерняя прогулка у моря в Shekou: Sea World, рестораны, набережная, район старого международного Шэньчжэня.
```

Для каждого места нужна короткая человеческая расшифровка:

- что это;
- зачем туда идти;
- сколько примерно времени;
- это прогулка, парк, трансфер, техническая остановка или главный смысл дня.

## 9. Время в пути и ритм дня

В каждой транспортной строке указывать время в пути:

- перелет — фактическое время рейса;
- трансфер аэропорт-аэропорт — диапазон;
- аэропорт-отель — диапазон;
- отель-парк — примерный мини-трансфер;
- поезд — ожидаемое время;
- вокзал-отель — диапазон.

Если точное время не куплено, писать:

```text
Оценка: 2.5–3.5 ч, уточнить после покупки билета.
```

## 10. Визуальная колонка

Правая колонка с изображениями — важная часть метода. Она превращает таблицу в плакат, но не ломает навигацию.

### 10.1. Какие изображения нужны

Подбирать не случайные картинки, а образы этапов:

- ночной перелет / крыло самолета;
- аэропорт Daxing;
- карстовые горы и река Ли / Юйлун;
- деревня или гостиница в Яншо;
- ночной Гуанчжоу и река;
- панды / тигры / сафари;
- Shekou / море / Shenzhen Bay;
- технологический Шэньчжэнь / BYD / Nanshan;
- Hilton у аэропорта;
- финальный самолет домой.

### 10.2. Стиль изображений

- мягкие светлые фото или фотореалистичные иллюстрации;
- не мультяшность, если документ взрослый;
- единая цветовая температура;
- скругленные углы;
- одинаковая ширина;
- без тяжелых теней;
- изображения не должны спорить с таблицей.

## 11. Иконки и номера этапов

Иконки помогают быстро сканировать маршрут.

Рекомендуемые иконки:

- самолет — перелет;
- машина — трансфер;
- поезд — железная дорога;
- дом/отель — размещение;
- лапа/панда — сафари/животные;
- волны/якорь — море;
- здания — город;
- часы — техническая остановка;
- галочка — задача выполнена / спокойно.

Иконки должны быть одного стиля: линейные, темно-бирюзовые или темно-синие, без разноцветного карнавала.

## 12. Плотность текста

Главное правило: каждая ячейка должна быть законченной, но не распухшей.

Рекомендуемый лимит:

- заголовок ячейки: 1 строка;
- основной текст: 2–4 короткие строки;
- детали: через компактные бейджи;
- длинные списки пассажиров переносить на отдельную строку.

Если текст не влазит:

- увеличить высоту строки;
- сократить формулировку;
- перенести детали в нижний блок документов;
- не уменьшать шрифт до нечитаемого размера.

## 13. Блок «купить заранее»

Внизу плаката должен быть отдельный контрольный блок:

```text
Купить заранее:
1. Трансфер KWL / Guilin Liangjiang T2 → Yangshuo
2. Поезд Guilin/Yangshuo → Guangzhou South
3. Поезд Guangzhou South → Shenzhen
```

Не смешивать это с планом дня. Это отдельный чек-лист действий.

## 14. HTML-версия

Если делается HTML, использовать ту же логику:

- `max-width` страницы около 1180–1280 px;
- светлый фон;
- карточки с мягкими границами;
- CSS variables для палитры;
- `grid-template-columns` для трех или четырех колонок;
- `overflow-wrap: anywhere` для длинных строк;
- единые классы для статусов `paid`, `check`, `todo`, `warning`;
- печатный режим `@media print`;
- избегать горизонтального переполнения;
- для мобильного режима превращать строки в вертикальные карточки.

### 14.1. Обязательные CSS-приемы

```css
*, *::before, *::after { box-sizing: border-box; min-width: 0; }
body { overflow-x: hidden; }
.cell { overflow-wrap: anywhere; }
.route-grid { display: grid; grid-template-columns: 1.25fr 1fr 1.15fr 160px; }
```

## 15. Контроль качества перед финалом

Перед тем как отдавать файл, пройти чек-лист:

- [ ] все аэропорты записаны в одном формате;
- [ ] все рейсы имеют дату, номер, время и пассажиров;
- [ ] однофамильцы/одноименные пассажиры различаются одинаково во всем документе;
- [ ] каждый отель имеет номер брони или confirmation/booking no.;
- [ ] все строки помещаются в карточки;
- [ ] нет текста, вылезающего за прямоугольники;
- [ ] нет ссылок `file:///G:/...` в финальном HTML;
- [ ] нет PIN-кодов, e-ticket numbers и лишних персональных данных;
- [ ] все «нужно купить» вынесено в отдельный блок;
- [ ] все сомнительные места отмечены как `ПРОВЕРИТЬ`, а не спрятаны.

## 16. Тон документа

Тон должен быть семейный, спокойный, уверенный:

- без рекламной истерики;
- без туристической попсы;
- без канцелярского холода;
- с ощущением маршрута, который уже почти живет.

Лучший результат — когда документ хочется не только использовать, но и сохранить как память о проектировании поездки.
