# Реестр бизнес-модулей

Статус: `Candidate`

Этот реестр хранит повторяемые бизнес-модули F-Engineering.

Модуль - это самостоятельный кирпичик работы, который можно подключать к разным
процессам компании. Он не равен всему бизнес-процессу, но может быть встроен в
несколько стадий: тендер, КП, проектирование, производство, монтаж, закрытие,
архив.

## Действующие и кандидатные модули

| ID | Модуль | Стадии применения | Пользователи результата | Основной результат | Статус |
|---|---|---|---|---|---|
| BPM-001 | [Первичная индексация входящей документации](modules/incoming-documentation-indexer/README.md) | Старт тендера / КП; старт проектирования; последующее обращение к входящим исходникам | Коммерсанты, проектировщики, руководители проектов, технические специалисты, участок | Сырой реестр файлов, сущности проекта, классифицированный реестр, HTML / Apps Script / Google Sheets просмотрщик | Candidate |
| BPM-002 | [Просмотрщик DWG-файлов](modules/BPM-002-dwg-viewer/README.md) | Старт тендера/КП; старт проектирования; архивное обращение к DWG | Коммерсанты, проектировщики, руководители проектов, технические специалисты, участок | Standalone HTML-навигатор по DWG с миниатюрами, путями, масштабом и pan | Approved |

## Как добавлять новый модуль

1. Проверить стандарт: [`MODULE_STANDARD.md`](MODULE_STANDARD.md).
2. Создать папку модуля в `business-processes/modules/`.
3. Описать модуль по единой карточке.
4. Добавить инструкцию оператору.
5. Добавить модель данных, если модуль создает таблицу, реестр или справочник.
6. Добавить критерии готовности.
7. Внести модуль в этот реестр.
8. Подключить модуль к карте процессов: [`PROCESS_MAP.md`](PROCESS_MAP.md).
9. Добавить запись в общий реестр знаний `registry/KNOWLEDGE_REGISTRY.md`.

## Когда модуль считается готовым к `Approved`

Модуль можно переводить из `Candidate` в `Approved`, если:

1. он применен хотя бы на одном рабочем или тестовом кейсе;
2. оператор может повторить работу по инструкции;
3. результат полезен целевому пользователю;
4. критерии готовности проверяемы;
5. клиентские данные не перенесены в GitHub;
6. модуль подключен к карте процессов;
7. есть понятное место для будущего развития.

## Правило повторного применения

Один модуль может применяться в нескольких стадиях.

Не создавать второй модуль только потому, что тот же механизм используется другим
отделом. Сначала проверить, можно ли расширить список стадий применения
существующего модуля.

Пример:

`BPM-001` применяется и на старте КП, и на старте проектирования, и позднее как
справочный архив. Это один модуль, потому что механизм один: собрать реестр,
создать сущности, классифицировать строки и дать быстрый доступ к файлам.
