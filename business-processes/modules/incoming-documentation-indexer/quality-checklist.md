# BPM-001. Чек-лист качества

Статус: `Candidate`

Этот чек-лист используется для проверки результата модуля первичной индексации
входящей документации.

## 1. Проверка сырого реестра

- [ ] Все видимые файлы из входящей папки попали в реестр.
- [ ] Для каждого файла есть имя.
- [ ] Для каждого файла есть расширение или формат.
- [ ] Для каждого файла есть полный путь или облачная ссылка.
- [ ] Зафиксирована родительская папка.
- [ ] Зафиксирована ветка папок / источник.
- [ ] Зафиксирован Google Drive file ID, если файл находится в Drive.
- [ ] Зафиксирована дата изменения, если доступна.
- [ ] Зафиксирован размер файла, если доступен.
- [ ] Нет очевидных потерь из-за фильтрации расширений.

## 2. Проверка сущностей

- [ ] Сущности выбраны после просмотра сырого реестра, а не заранее вслепую.
- [ ] Не создано лишних колонок, которые не помогают поиску или фильтрации.
- [ ] Есть минимальный набор для поиска: тип документа, формат, источник / папка,
      статус.
- [ ] При необходимости добавлены корпус, секция, фасад, ось, раздел, стадия,
      версия или ревизия.
- [ ] Значения сущностей читаются человеком и не превращены в случайный набор
      технических кодов без расшифровки.

## 3. Проверка классификации

- [ ] Важные файлы классифицированы достаточно для фильтрации.
- [ ] Фасады, планы, разрезы, узлы, спецификации и DWG/PDF пары выделены, если они
      присутствуют.
- [ ] Сомнительные строки помечены как `requires review`.
- [ ] Архивные и дублирующие файлы не смешаны с рабочими без статуса.
- [ ] Нет молчаливой уверенной классификации там, где имя файла или путь
      неоднозначны.

## 4. Проверка просмотрщика или рабочих представлений

- [ ] Пользователь может открыть одну точку входа: Google Sheet, HTML, Apps Script
      Web App или другой согласованный интерфейс.
- [ ] Есть поиск или фильтры по ключевым сущностям.
- [ ] Ссылки на файлы открываются.
- [ ] PDF-файлы можно быстро найти и открыть.
- [ ] Просмотрщик не перегружен фильтрами, которые не нужны целевому пользователю.
- [ ] Если используется HTML, он соответствует актуальному визуальному стилю из
      `docs/F_ENGINEERING_VISUAL_STYLE.md`.

## 5. Проверка пользователем

Попросить целевого пользователя найти через результат модуля:

- [ ] PDF фасада;
- [ ] PDF разреза;
- [ ] DWG-аналог или исходный DWG;
- [ ] спецификацию или иной важный исходный документ;
- [ ] файл, который раньше было трудно найти вручную.

Модуль считается успешным, если пользователь находит эти файлы через реестр или
просмотрщик быстрее, чем через ручное перемещение по папкам.

## 6. Проверка безопасности и GitHub

- [ ] Клиентские файлы не перенесены в GitHub.
- [ ] Коммерческие цены, КП поставщиков и конфиденциальные расчеты не перенесены в
      GitHub.
- [ ] В GitHub сохранены только метод, инструкция, структура, правила и
      обезличенные примеры.
- [ ] В рабочей проектной папке размещена ссылка на актуальный реестр или
      просмотрщик.

## 7. Решение по статусу

После проверки выбрать статус:

| Статус | Когда применять |
|---|---|
| `OK` | Модуль выполнен, результат можно использовать |
| `Needs review` | Реестр собран, но сущности или классификация требуют проверки |
| `Incomplete` | Не все файлы попали в реестр или нет рабочей точки входа |
| `Rejected` | Результат нельзя использовать, модуль нужно выполнить заново |
