# Модель данных: первичная индексация входящей документации

Статус: `Candidate`

Модель данных должна быть гибкой. На разных объектах нужны разные сущности, но
у реестра должен оставаться стабильный минимальный набор полей, чтобы будущие
просмотрщики и автоматизации могли переиспользовать структуру.

## Базовые поля

| Поле | Значение | Обязательно |
|---|---|---|
| `file_name` | Имя файла с расширением | Да |
| `extension` | Расширение / формат файла | Да |
| `local_path` | Локальный путь подключенного диска, если есть | Нет |
| `drive_url` | Ссылка Google Drive | Нет |
| `drive_file_id` | Google Drive file ID | Нет |
| `folder_path` | Полный путь к исходной папке | Да |
| `parent_folder` | Непосредственная родительская папка | Да |
| `source_branch` | Основная ветка папок или пакет исходных данных | Да |
| `modified_at` | Дата изменения файла | Нет |
| `size` | Размер файла | Нет |
| `status` | Статус классификации | Да |
| `comment` | Комментарий человека | Нет |

## Рекомендуемые сущности

Добавлять только те поля, которые помогают конкретному проекту.

| Сущность | Примеры |
|---|---|
| `project` | OD-150, корпус A, тендер 2026 |
| `building` | корпус 1, корпус 2, block A |
| `section` | A1, A2, AS3 |
| `discipline` | AR, AS, KM, facade, MEP |
| `document_type` | plan, facade, section, node, specification, report |
| `work_type` | SPK, ventilated facade, cornice, plaster, stone |
| `stage` | incoming, tender, design, production, archive |
| `package` | client package 01, дополнительные вопросы, revised issue |
| `revision` | Rev00, Rev01, версия по дате |
| `view_group` | incoming drawings, commercial, design, suppliers |

## Статусы классификации

Использовать небольшой набор статусов:

- `classified` - файл отнесен к нужным сущностям;
- `requires review` - файл есть, но классификация сомнительна;
- `duplicate` - дубль или почти дубль другого файла;
- `archive` - старый или архивный файл, сохранен для справки;
- `excluded` - файл существует, но не используется в текущем просмотрщике.

## Поля просмотрщика

Просмотрщик должен использовать только те поля, которые нужны текущему
интерфейсу.

Типовые фильтры:

- поиск;
- секция;
- тип документа;
- вид работ;
- формат;
- ветка источника.

Не нужно добавлять фильтр только потому, что соответствующая колонка есть в
реестре. Избыточное количество фильтров ухудшает работу пользователя.
