# Заметки по реализации: первичная индексация входящей документации

Статус: `Candidate`

## Варианты реализации

Модуль можно реализовывать с разной глубиной в зависимости от сложности объекта.

## Вариант A. Статический реестр и статический HTML

Порядок:

1. просканировать папки;
2. создать реестр;
3. классифицировать файлы;
4. сгенерировать один самостоятельный HTML-просмотрщик.

Применять, когда:

- пакет документов в основном стабилен;
- команде нужен быстрый просмотрщик;
- обновления редкие.

## Вариант B. Google Sheets реестр и HTML-просмотрщик

Порядок:

1. просканировать папки в Google Sheets;
2. классифицировать файлы в таблице;
3. сгенерировать HTML из таблицы;
4. опубликовать просмотрщик.

Применять, когда:

- классификация требует проверки человеком;
- у проекта много сущностей;
- несколько людей должны смотреть или корректировать реестр.

## Вариант C. Живой Apps Script просмотрщик

Порядок:

1. Apps Script читает папку Google Drive;
2. правила классифицируют файлы по пути и имени;
3. просмотрщик строит актуальный список при открытии;
4. сомнительные файлы помечаются для проверки.

Применять, когда:

- папка часто меняется;
- команда принимает права и ограничения Apps Script;
- правила именования достаточно стабильны для автоматической классификации.

Риск:

- без ясных правил именования живой просмотрщик будет давать шумную
  классификацию.

## Рекомендуемый вариант по умолчанию

Начинать с варианта B.

Google Sheets является проверяемым слоем классификации. HTML или Apps Script
является только витриной. Такой подход понятен оператору и легко исправляется,
если имена файлов непоследовательны.

## Роль GitHub

GitHub хранит:

- методику;
- модель данных;
- инструкцию оператору;
- переиспользуемые скрипты и шаблоны;
- обезличенные примеры.

GitHub не хранит:

- клиентские PDF/DWG;
- архивы исходников проекта;
- цены поставщиков;
- коммерческие предложения;
- конфиденциальные расчеты.
