# Data model: BPM-002 DWG viewer

## Вход

Входом является папка с DWG-файлами. Сборщик обходит ее рекурсивно и берет только файлы с расширением `.dwg` без учета регистра.

## Реестр

Каждый DWG превращается в запись реестра:

| Поле | Назначение |
|---|---|
| `id` | Стабильный ID внутри HTML, например `dwg-0001`. |
| `file_name` | Имя DWG-файла. |
| `relative_path` | Путь от корня входной папки. |
| `size_bytes` | Размер исходного DWG в байтах. |
| `dxf_path` | Локальный путь к промежуточному DXF в рабочей папке. |
| `preview_file` | Имя SVG-превью в рабочей папке. |
| `preview_data_uri` | Встроенное SVG-превью как `data:image/svg+xml;base64,...`. |
| `status` | `ok`, `missing_dxf`, `render_failed` или другой технический статус. |
| `error` | Текст ошибки, если превью не создано. |

## HTML

HTML является standalone-файлом. Он содержит:

- CSS интерфейса;
- JavaScript навигации, масштаба и панорамирования;
- JSON-реестр DWG;
- встроенные SVG-превью в `preview_data_uri`.

HTML не должен требовать доступа к исходным DWG, DXF, SVG или AutoCAD.

## Preview pipeline

```text
DWG folder -> ODA File Converter -> DXF folder -> ezdxf SVG render -> registry.json -> standalone HTML
```

## Layout rules

- Левая колонка: миниатюра, имя файла, относительный путь.
- Правая область: название выбранного DWG, инструменты масштаба, большое SVG-превью.
- На компьютере используется двухколоночная схема.
- На телефоне используется вертикальная схема: список сверху, просмотр снизу.
- В горизонтальной ориентации телефона шапки должны быть компактными.

## Storage rules

В GitHub допускаются:

- этот data model;
- инструкции;
- скрипты сборки;
- требования к качеству.

В GitHub не допускаются:

- клиентские DWG;
- промежуточные DXF;
- SVG-превью клиентских файлов;
- standalone HTML с клиентскими данными;
- `registry.json`, созданный по клиентскому проекту.
