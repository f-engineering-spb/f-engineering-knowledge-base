# Визуальный стиль цифровых продуктов F-Engineering

> **ID**: DS-011  
> **Статус**: Candidate  
> **Назначение**: единый машинный стиль интерфейсов цифровых продуктов и служебных интерактивных артефактов.

---

## 1. Область применения

Стандарт применяется к:

- лаунчерам, рабочим панелям и интерфейсам программ;
- интерактивным HTML-просмотрщикам и навигаторам;
- служебным интерфейсам модулей, журналам выполнения и системным карточкам;
- машинно оформленным служебным Markdown-артефактам, предназначенным для работы как с техническим интерфейсом;
- прототипам цифровых продуктов F-Engineering.

Стандарт не применяется к договорам, КП, отчётам, таблицам, презентациям, методичкам и другим выдаваемым документам. Для них действует `DS-010`.

## 2. Визуальный принцип

Интерфейс строится как спокойная профессиональная IDE-среда: тёмная графитовая основа, компактная информационная плотность, моноширинная типографика, сине-металлический акцент и ограниченные семантические цвета.

Декор не должен конкурировать с содержанием. Цвет обозначает состояние, действие или структуру.

## 3. Базовая палитра DP01 — Machine Blue

| Роль | Цвет | Применение |
|---|---|---|
| Background | `#0D1117` | основной фон |
| Surface | `#161B22` | панели и дерево |
| Elevated | `#1F2630` | карточки, поля, активные области |
| Border | `#30363D` | границы и разделители |
| Text | `#E6EDF3` | основной текст |
| Text muted | `#8B949E` | подписи и вторичные данные |
| Primary | `#58A6FF` | активное действие, ссылка, выделение |
| Primary strong | `#1F6FEB` | основная кнопка и выбранный элемент |
| Success | `#3FB950` | готово, корректно |
| Warning | `#D29922` | ожидание и предупреждение |
| Danger | `#F85149` | ошибка и остановка |
| Info | `#BC8CFF` | системная или AI-информация |

Градиенты допустимы только как слабый металлический нюанс фона или активного элемента. Они не заменяют семантические цвета.

## 4. Типографика

Основной шрифт интерфейса:

`JetBrains Mono, SFMono-Regular, Cascadia Code, Consolas, Liberation Mono, monospace`.

Для длинных пояснений внутри продукта допустим нейтральный системный шрифт, но управляющие элементы, пути, статусы, дерево, журналы и служебные Markdown-блоки оформляются моноширинно.

## 5. Компоненты

- Основные действия выделяются синим; на одном экране должна быть одна визуально главная кнопка.
- Успех, предупреждение и ошибка обозначаются зелёным, жёлтым и красным соответственно.
- Панели разделяются тонкими границами, без тяжёлых теней.
- Дерево, редактор запроса и рабочая область могут изменять размер; активный разделитель получает синий акцент.
- Системные сообщения короткие, пригодные для сканирования.
- Пути и имена файлов отображаются без декоративного шрифта и без усечения, скрывающего значимую часть.
- Контраст текста и управляющих элементов должен оставаться достаточным во всех состояниях.

## 6. Служебный Markdown

Обычные файлы правил и реестров GitHub сохраняют стандартную переносимую Markdown-разметку без встроенного оформления.

Если Markdown является самостоятельным служебным продуктом или частью IDE-подобного интерфейса, его визуальное представление следует DP01: моноширинный шрифт, тёмные поверхности, подсветка кода и семантические акценты. Исходный `.md` при этом должен оставаться читаемым без специального просмотрщика.

## 7. Совместная работа DS-010 и DS-011

| Результат | Стандарт |
|---|---|
| интерфейс лаунчера или модуля | DS-011 |
| интерактивный технический навигатор | DS-011 |
| служебный машинный Markdown-продукт | DS-011 |
| реестр, отчёт, КП, договор, презентация | DS-010 |
| экспорт документа из цифрового продукта | DS-010 |
| оболочка продукта с документом внутри | оболочка DS-011, документ DS-010 |

## 8. Изменения

Новые продуктовые палитры и существенные изменения компонентов вносятся через Pull Request с примером интерфейса и проверкой читаемости.
