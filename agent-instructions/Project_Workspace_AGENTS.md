# Инструкция агента для проектной рабочей папки

## Назначение

Применять эту инструкцию при работе в конкретной проектной папке на Google
Drive, общем диске или локальном компьютере.

## Перед началом работы

1. Использовать ветку `main` репозитория
   `f-engineering-spb/f-engineering-knowledge-base` как источник утвержденных
   общих правил.
2. Прочитать `START_HERE.md`, корневой `AGENTS.md` и применимые инструкции.
3. Определить цель проекта, рабочую папку, исходные данные и необходимые
   выходные формы.
4. Не переносить проектные и клиентские материалы в базу знаний.

## Организация проектной папки

- исходные материалы хранить отдельно и не изменять;
- рабочие расчеты и черновики хранить отдельно от результатов;
- выдаваемые документы проводить через статусы `review`, `final` и `sent`;
- действующую версию результата указывать в индексе проекта;
- значимые решения и допущения фиксировать письменно.

## Русские пути, кириллица и чертежные файлы

В проектных папках F-Engineering считать кириллицу, пробелы, скобки, длинные имена
файлов и вложенные папки нормой. Перед обработкой файлов выбирать приемы, которые
устойчивы к таким путям.

- В PowerShell использовать `-LiteralPath` для путей к проектным папкам и файлам.
- Не полагаться на табличный вывод для длинных путей: выводить полные имена
  построчно, например через `ForEach-Object { $_.FullName }`.
- Для сложной обработки, циклов, фильтрации PDF или путей с кириллицей создавать
  небольшой временный скрипт в рабочей области вместо длинной команды в одну
  строку.
- При чтении текстов явно учитывать кодировку `UTF-8` и `Windows-1251`; если
  вывод выглядит поврежденным, повторить чтение с другой кодировкой или другим
  способом извлечения.
- Для чертежей сначала анализировать PDF-копии, если рядом с DWG есть файл с тем
  же или почти тем же именем в формате PDF.
- DWG/DXF открывать или анализировать только если PDF-копии нет, если PDF
  недостаточен для ответа, или если пользователь прямо попросил работать с DWG.
- При извлечении текста из чертежных PDF проверять результат визуально: шрифты в
  PDF могут быть закодированы так, что текстовый поиск не находит видимые надписи.
- Если текст PDF не извлекается надежно, делать растровые превью нужных листов и
  фиксировать, какие листы проверены визуально.

## Применение базы знаний

- стандарты документов брать из `document-standards/`;
- методы выполнения работ брать из `methodologies/`;
- шаблоны брать из `templates/`;
- повторно используемые инструменты брать из `tools/`;
- подтвержденные рабочие предпочтения учитывать из
  `agent-instructions/User_Working_Preferences.md`.

## Новые знания

Если в проекте появился полезный повторно используемый подход:

1. Оставить проектный результат в проектной папке.
2. Подготовить отдельный обезличенный кандидат для базы знаний.
3. Описать назначение, область применения и ограничения.
4. Внести кандидат через отдельную ветку и Pull Request.
