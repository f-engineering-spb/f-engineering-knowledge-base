# Структура результатов аудита

## Размещение

Исходники сохранять в:

`01_Input/<Проект>/<Комплект>/`

Рабочие результаты сохранять в:

`02_Drafts/<Проект>/<Комплект>_Audit/`

Рекомендуемая структура рабочей папки:

```text
<Комплект>_Audit/
├── 01_Extracted/       извлеченный текст, слои, превью и реестры
├── 02_Calculations/    расчетные таблицы и промежуточные данные
├── 03_Control/         перекрестные проверки и проверочный лист
└── 04_Report/          полный HTML-отчет и приложения
```

Для небольших задач разрешено хранить результаты непосредственно в `02_Drafts/<Проект>`, но полный отчет и проверочный лист все равно обязательны.

## Обязательные файлы

Рекомендуемые имена:

```text
YYYY-MM-DD_<Проект>_<Комплект>_FullAudit_draft_v01.html
YYYY-MM-DD_<Проект>_<Комплект>_ControlSheet_draft_v01.html
YYYY-MM-DD_<Проект>_<Комплект>_QuantityRegister_draft_v01.xlsx
YYYY-MM-DD_<Проект>_<Комплект>_DiscrepancyRegister_draft_v01.xlsx
```

## Поля расчетного реестра

Каждая позиция должна содержать:

- уникальный идентификатор;
- читаемую марку позиции по категории: например, `К1`, `К2` для кассет;
- файл, лист, вид и оси;
- категорию и материал;
- исходные размеры;
- формулу;
- необработанное значение;
- итоговое округленное значение;
- единицу измерения;
- статус достоверности A/B/C/D;
- метод проверки;
- разницу между методами;
- комментарий и исключения.

## Представление итогов

- Полный отчет: подробная доказательная база.
- Проверочный лист: одна короткая проверочная панель без лишнего текста.
- Реестр количеств: фильтруемые исходные позиции и формулы.
- Реестр расхождений: только вопросы, требующие решения.

## Представление спецификаций повторяемых изделий

Для кассет, панелей, стеклопакетов, окон, дверей, ламелей и аналогичных повторяемых изделий:

- использовать одну сводную таблицу, одна строка на типоразмер/марку;
- не выводить каждый типоразмер отдельной карточкой;
- обязательные столбцы: марка, размер, количество, площадь позиции, достоверность;
- добавлять закрепленную итоговую строку с общим количеством и суммарной площадью;
- марки присваивать последовательно по категории: `К1…Кn` для кассет, если проектом не заданы авторские марки;
- заголовки и значения в ячейках спецификации центрировать по горизонтали и вертикали;
- числовые значения оформлять единообразно и проверять контрольной суммой;
- для длинной ведомости использовать закрепленную шапку и прокрутку внутри контейнера таблицы.
