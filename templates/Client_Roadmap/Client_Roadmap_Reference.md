# Эталон клиентской дорожной карты

Статус: `Reference`

Этот файл заменяет прежний HTML-эталон и фиксирует reusable-структуру
клиентской дорожной карты без хранения готового HTML-документа в базе знаний.

## Назначение

Использовать как структурный эталон для дорожных карт запуска, создания,
внедрения, восстановления и масштабирования проектов, объектов, функций,
направлений и производств.

## Каркас документа

```text
Титульный блок
→ Содержание
→ Резюме проекта
→ Актуальная конфигурация
→ План запуска
→ Финансовый блок
```

## Титульный блок

Содержит:

- eyebrow: `Проект · тип документа`;
- H1: название дорожной карты;
- краткое описание целевого результата;
- метаданные: дата, версия, срок или период.

Визуальное ядро титульного блока описано в
`document-standards/Client_Roadmap_Style.md`.

## Содержание

В настольной HTML-версии допускается боковое содержание.
В Markdown-эталоне фиксируется логика разделов:

1. Резюме.
2. Конфигурация.
3. План запуска.
4. Финансовый блок.

## Резюме проекта

Резюме должно содержать 3-5 KPI или ключевых управленческих показателей.

Формат KPI:

| Показатель | Короткое пояснение |
|---|---|
| Показатель | Короткое пояснение |
| Показатель | Короткое пояснение |
| Показатель | Короткое пояснение |

## Актуальная конфигурация

Использовать таблицу, которая показывает состояние и действие по каждому
самостоятельному направлению или контуру.

| Направление | Текущее состояние | Требуемое действие |
|---|---|---|
| Направление | Описание | Действие |

## План запуска

Показывать 3-5 последовательных этапов. Каждый этап формулировать через
достигаемый результат, а не через внутренний процесс анализа.

| Этап | Название | Результат этапа |
|---|---|---|
| Этап 1 | Название | Результат этапа |
| Этап 2 | Название | Результат этапа |
| Этап 3 | Название | Результат этапа |
| Этап 4 | Название | Результат этапа |

## Финансовый блок

В основном документе показывать сводные финансовые показатели.
Детальный расчет выпускать отдельной XLSX-моделью.

## Обязательные правила применения

1. До оформления разложить исходные данные по смысловым контурам.
2. Сохранить логическую цепочку:

   ```text
   цель → контуры → ресурсы → результат → дефициты → люди → этапы → риски → финансы
   ```

3. Не переносить внутреннюю историю анализа в клиентский документ.
4. Финансовые расчеты размещать отдельным блоком и, при необходимости, отдельной XLSX-моделью.
5. Для HTML-реализации соблюдать мобильный стандарт и фирменную палитру из профильного стандарта.
