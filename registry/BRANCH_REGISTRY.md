# Реестр веток базы знаний

Статус: `Approved`

Этот файл нужен, чтобы экспериментальные правила не смешивались с действующими правилами ветки `main`.

## Принцип

`main` содержит только действующие или явно зарегистрированные знания.

Экспериментальные ветки используются для подготовки новых правил, но не считаются обязательными для всех задач, пока изменения не объединены в `main`.

## Правила именования веток

| Тип ветки | Формат | Пример |
|---|---|---|
| Новая методика | `codex/rules-<workflow-name>` | `codex/rules-equipment-video-audit` |
| Новый стиль документа | `codex/style-<format-or-purpose>` | `codex/style-sendable-html` |
| Управление базой знаний | `codex/governance-<topic>` | `codex/governance-application-map` |
| Исправление существующего правила | `codex/fix-<rule-id-or-topic>` | `codex/fix-html-mobile-tables` |

## Что указывать в Pull Request

Каждый PR с новым правилом должен содержать:

1. Что добавлено или изменено.
2. Из какого проекта или кейса возникло правило.
3. Какой статус предлагается: `Candidate`, `Pilot` или `Approved`.
4. Какие записи реестра обновлены.
5. Какие существующие правила дополняются или уточняются.
6. Есть ли риск конфликта.

## Когда ветку закрывать

Ветку можно закрыть после merge в `main` и обновления:

- `registry/KNOWLEDGE_REGISTRY.md`;
- `registry/APPLICATION_MAP.md`;
- этого файла, если направление больше не активно.
