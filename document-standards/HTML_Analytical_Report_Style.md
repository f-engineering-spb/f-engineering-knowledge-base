# Стиль HTML-аналитических отчетов

## Обязательное применение

Для аналитических записок, исследований, классификаторов, нормативных обзоров, технических отчетов и подобных содержательных HTML-документов использовать стиль эталона:

`templates/HTML_Analytical_Report/Analytical_Report_Reference.html`

Эталон создан на основе отчета проекта `Glass_Defect_AI` и утвержден пользователем 07.06.2026.

## Характер стиля

- спокойный современный деловой вид;
- темно-синяя и бирюзово-синяя цветовая гамма;
- шрифт `Segoe UI`, с резервными `Arial, sans-serif`;
- крупный градиентный титульный блок;
- компактные метаданные в плашках;
- белая рабочая область на светло-сером фоне;
- закрепленное содержание слева в настольной версии;
- удобная прокрутка длинного документа и кнопка возврата наверх;
- четкая иерархия заголовков;
- аккуратные таблицы с темно-синими шапками;
- на телефоне обычные аналитические таблицы превращаются в карточки; расчетные спецификации могут сохраняться единой таблицей;
- отдельный печатный режим.

## Обязательные технические требования

### Встроенные проверочные превью

HTML-отчёты с рассчитанными или извлечёнными объёмами обязаны содержать
проверочные превью непосредственно в основном отчёте.

После соответствующей таблицы или расчётного раздела использовать
раскрываемый блок:

```html
<details>
  <summary>Проверочный лист: файл, лист и категория объёмов</summary>
  <img src="..." alt="Полный исходный лист">
</details>
```

Показывать полный исходный лист или страницу в читаемом разрешении.
Увеличенный фрагмент допускается только дополнительно. В заголовке указывать
исходный файл, страницу PDF, номер листа и проверяемую категорию.

При конфликте между краткостью документа и проверяемостью приоритет имеет
проверяемость.

1. Соблюдать `document-standards/HTML_Mobile_Standard.md`.
2. На viewport телефона горизонтальная прокрутка не допускается.
3. Проверять:

```text
document.documentElement.scrollWidth <= document.documentElement.clientWidth
```

4. На ширине до 600 px обычные широкие таблицы преобразовывать в карточки с подписями полей. Для расчетных спецификаций повторяемых изделий сохранять единую таблицу с прокруткой только внутри контейнера таблицы.
5. Сохранять интерактивное содержание и кнопку возврата наверх для длинных документов.
6. Не менять основную палитру, типографику и композицию без прямой просьбы пользователя.

## Допустимая адаптация

Разрешено менять заголовок, подзаголовок, метаданные, состав разделов, таблиц и предупреждений. Визуальную систему эталона сохранять.

## Базовые параметры и выбор палитры

При оформлении аналитических HTML-отчетов должны соблюдаться следующие базовые требования:
- **Основной текст**: `#1f2328`
- **Вторичный текст**: `#59636e`
- **Базовая граница**: `#d9dedc`
- **Шрифт**: `Segoe UI, -apple-system, BlinkMacSystemFont, Helvetica Neue, Arial, sans-serif`
- **Моноширинный шрифт**: `Segoe UI Mono, Consolas, Courier New, monospace`

### Выбор утверждённой палитры
Аналитические HTML-отчеты должны оформляться строго по одной из 7 палитр (`P01`–`P07`) в прямой (Direct) или инверсной (Inverted) схеме в зависимости от назначения:
- **GitHub / правила / реестры / таблицы** &rarr; `P01 Direct` (GitHub Light)
- **Универсальный рабочий HTML / просмотрщик** &rarr; `P02 Direct` (Apple Gray)
- **Методичка / длинное чтение** &rarr; `P03 Direct` (Warm Paper)
- **Регламент / бизнес-процесс** &rarr; `P04 Direct` (Sage)
- **Техническая аварийная инструкция** &rarr; `P05 Direct` (Sand)
- **Сравнение / варианты решений** &rarr; `P06 Direct` (Mist Lavender)
- **AI-инструмент / технологическая матрица** &rarr; `P07 Direct` (Ice Blue)

Использование инверсной (Inverted) схемы допускается только тогда, когда требуется более насыщенный фон и светлые карточки/элементы на нём.
