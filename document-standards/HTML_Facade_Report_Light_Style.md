# Лёгкий стиль HTML-отчётов по фасадному аудиту

Статус: `Approved`

## Назначение

Этот стандарт применяется для клиентских HTML-отчётов по фасадному аудиту,
проверке ведомостей, опросным листам по границам расчёта и фасадным
спецификациям для коммерческих предложений.

Стиль нужен для длинных отчётов с большим количеством таблиц, проверочных
листов и встроенных изображений, когда насыщенный тёмный титульный блок
начинает визуально давить и утомлять читателя.

## Приоритет применения

Для фасадных клиентских отчётов по умолчанию использовать именно этот лёгкий
стиль.

Более насыщенный аналитический стиль из
`document-standards/HTML_Analytical_Report_Style.md` остаётся допустимой
альтернативой, когда нужен презентационный, акцентный или «боевой» вид
документа.

Если пользователь прямо просит «боевую раскраску», «презентационный вид» или
насыщенный фирменный градиент, применять общий аналитический стиль. Если
пользователь просит документ для спокойного чтения заказчиком, использовать
лёгкий фасадный стиль.

## Характер стиля

- почти белый лист;
- мягкие сине-зелёные акценты;
- минимум тёмных заливок;
- тонкие линии и слабые тени;
- таблицы читаются как инженерный документ, а не как рекламная презентация;
- проверочные изображения встроены в документ, но визуально не спорят с
  текстом;
- титульный блок светлый, без тяжёлого тёмного градиента.

## Палитра

Использовать следующую базовую палитру:

```css
:root {
  --ink: #20323a;
  --muted: #72838a;
  --brand-dark: #456f78;
  --brand: #6fa7ad;
  --brand-accent: #5d969d;
  --brand-pale: #f3faf9;
  --brand-soft: #eaf4f3;
  --paper: #ffffff;
  --bg: #f8fbfb;
  --line: #dfe9eb;
  --line-soft: #edf3f4;
  --warn: #fffaf0;
  --bad: #fff4f1;
  --good: #f2fbf6;
}
```

## Титульный блок

Основной вариант титульного блока должен быть максимально светлым:

```css
.hero {
  background: linear-gradient(135deg, #ffffff 0%, #fbfdfd 62%, #f7fbfb 100%);
  color: var(--ink);
  border: 1px solid #e8f0f1;
  border-radius: 24px;
  padding: 30px;
  box-shadow: 0 8px 18px rgba(69, 111, 120, .035);
}
```

Допустим более заметный, но всё ещё светлый вариант:

```css
.hero {
  background: linear-gradient(135deg, #fafdfe 0%, #f3faf9 58%, #eaf4f3 100%);
  color: var(--ink);
  border: 1px solid var(--line);
  border-radius: 24px;
  padding: 30px;
  box-shadow: 0 12px 30px rgba(69, 111, 120, .08);
}
```

Тёмный фирменный градиент в фасадных отчётах применять только по прямой
просьбе пользователя.

## Таблицы

Шапки таблиц делать светлыми:

```css
th {
  background: #edf5f5;
  color: #294952;
  border-bottom: 1px solid var(--line);
}
```

Не использовать тёмно-синюю или тёмно-зелёную заливку шапок таблиц в
длинных фасадных отчётах для заказчика.

Расчётные таблицы с большим числом колонок можно оставлять как единую
таблицу в контейнере с локальной горизонтальной прокруткой.

## Обязательные содержательные элементы

Лёгкий стиль не отменяет требований методик фасадного аудита.

Отчёт должен сохранять:

- резюме и вывод о доверии к исходной ведомости;
- спецификацию с источниками, формулами и статусами `A/B/C/D`;
- перечень найденных сверх исходной ведомости конструкций;
- матрицу полноты фасадного состава;
- вопросы заказчику по границам расчёта;
- встроенные проверочные листы;
- реестр источников или ссылки на источники в расчётных строках.

## Проверочные превью

Для отчётов с объёмами применять правило
`proposals/Embedded_Verification_Previews_for_HTML_Reports.md`.

Проверочные листы в лёгком стиле оформлять спокойными раскрываемыми блоками:

```css
details {
  border: 1px solid var(--line);
  border-radius: 16px;
  background: #fff;
}

summary {
  background: #f3faf9;
  color: #385d66;
}
```

Изображения должны быть встроены в HTML через `data:image/...;base64`, если
документ предназначен для отправки одним файлом.

## Мобильность

Всегда соблюдать `document-standards/HTML_Mobile_Standard.md`.

Критичные правила:

```css
html, body {
  max-width: 100%;
  overflow-x: hidden;
}

*, *::before, *::after {
  box-sizing: border-box;
  min-width: 0;
}

img, svg, canvas {
  max-width: 100%;
  height: auto;
}
```

На мобильном экране структура должна переходить в одну колонку, а широкие
расчётные таблицы должны прокручиваться только внутри своего контейнера.

## Контроль готовности

Перед передачей клиентского фасадного HTML:

1. Проверить, что документ открывается одним файлом.
2. Проверить, что изображения встроены или поставляются вместе с HTML.
3. Проверить отсутствие сломанных символов и групп `????`.
4. Проверить, что титульный блок и таблицы визуально светлые.
5. Проверить, что нет горизонтального выпадения всей страницы на телефоне.
6. Проверить, что расчётные строки содержат источники и статусы.
