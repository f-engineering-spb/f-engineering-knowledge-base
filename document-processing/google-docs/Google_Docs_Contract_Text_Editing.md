# Google Docs Contract Text Editing

Статус: `Candidate`

Назначение: методика смысловой правки договоров и приложений в Google Docs / methodology for contract wording amendments in Google Docs.

Методика применяется, когда нужно изменить смысл, формулировку, пункт, таблицу или приложение договора без потери форматирования / preserving formatting.

## Базовый принцип

Работа идет по схеме:

`указание пользователя → черновик на экран → согласование → точечная правка → контрольное чтение`

`user instruction → draft preview → approval → targeted edit → verification read`

Документ не меняется до явного подтверждения пользователя.

## Рабочий протокол

1. Принять задачу пользователя и выделить смысл изменения / intended meaning.
2. Определить, какой фрагмент документа затрагивается: пункт, раздел, таблица, приложение, строка цены, календарный план.
3. Сначала подготовить черновик на экран / draft preview.
4. В черновике показать новую редакцию, место вставки или замены и краткую логику размещения.
5. Дождаться подтверждения пользователя.
6. Если пользователь уточняет формулировку, доработать черновик на экране и снова показать.
7. После прямого подтверждения внести только согласованный фрагмент.
8. Не менять соседние пункты, если пользователь этого не просил.
9. После записи перечитать измененный участок / verification read.
10. Сообщить пользователю, что именно изменено и что не трогалось.

## Правка пунктов договора

Если нужно заменить пункт договора / replace a contract clause:

1. Найти текущий пункт по точному тексту или по структуре документа.
2. Проверить границы пункта и соседние пункты.
3. Если пункт является элементом автоматического списка / automatic list item, не дробить его на несколько абзацев без необходимости.
4. Для длинной редакции на экране можно показывать несколько абзацев для читабельности, но в документ вставлять один цельный пункт, если нужно сохранить нумерацию.
5. После замены проверить, что следующий пункт остался на месте и нумерация не распалась.

## Правка таблиц и приложений

Если нужно поменять таблицу / table edit:

1. Сначала показать расчет на экран.
2. Проверить арифметику: строки, проценты, НДС, итоги.
3. Получить подтверждение пользователя.
4. Не использовать глобальную замену, если сумма может встречаться в нескольких местах.
5. Для нескольких сумм в таблице использовать точечную замену по конкретным ячейкам или диапазонам.
6. После записи перечитать приложение и вывести итоговую проверку.

## Безопасная запись

Предпочтительный подход / preferred approach:

1. Читать документ перед записью.
2. Вносить только согласованный фрагмент.
3. Избегать полной перезаписи документа.
4. Избегать глобальных замен без проверки уникальности совпадения.
5. После записи читать измененный участок повторно.

Если документ изменился между чтением и записью / revision mismatch:

1. Остановиться.
2. Перечитать документ.
3. Получить актуальные границы изменяемого фрагмента.
4. Повторить только согласованную правку.

## Отчет пользователю после правки

Финальный ответ должен содержать:

- ссылку на Google Docs документ;
- какой пункт, раздел или приложение изменены;
- что именно стало новым;
- что проверено повторным чтением;
- что не изменялось.

## Проверенный прием из пилота

Подтвержденный подход:

1. Пользователь описывает смысл изменения обычным языком.
2. Агент формирует договорную формулировку на экране.
3. Пользователь проверяет формулировку и уточняет термины.
4. Агент дорабатывает текст до согласования.
5. Агент вносит изменение только после прямой команды пользователя.
6. Агент проверяет результат повторным чтением и сообщает итог.

## Что не хранить в правиле

Не записывать в это правило клиентские данные, номера договоров, реквизиты, конкретные суммы, персональные данные и полный текст клиентских документов.

Правило хранит только методику / methodology.
